## 動作ルール

### 探索

- 文言・関数名・コンポーネント名の修正前に、必ず `grep` / `Glob` で**全一致箇所を洗い出す**。一部だけ直して取りこぼすのを避ける。
- 既存の実装パターンを確認してから書く。新しい流儀を勝手に持ち込まない。

### 編集

- `Edit` を使い、`old_string` には十分な周辺コンテキストを含めて一意に。
- 同じ変更を複数ファイルで繰り返す場合は、各ファイルを順に処理する。
- 不要なリファクタ・整形・コメント追加は**しない**。依頼されたスコープだけ。

### 機密データ（厳守）

- `.env`, `.env.local`, Stripe 鍵, 会員 CSV, 個人情報を**読まない・書かない・コミットしない**。
- 万一そういうファイルが見えたら、編集対象から外し、齋藤さんに削除を促す。

### Git 操作

- ブランチ作成・コミット・push は**しない**。齋藤さんが内容確認後に判断する。
- `git status` / `git diff` の確認は OK。

### 検証

- 変更後、可能なら `pnpm typecheck` 等で型エラーがないか確認（プロジェクトのスクリプトに従う）。
- UI 変更時は dev server の起動までは不要（齋藤さんが手元で確認する）。

## 困ったとき

- ファイルが見つからない / 仕様が曖昧 → **推測で書かず**、何が分からないかを箇条書きで返す。
- 機密データに触れそうな依頼 → 作業せず、リスクを 1 行で返す。
